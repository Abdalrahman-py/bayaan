1. What this project is (plain version)

Millions of people learn to recite the Qur'an, governed by Tajweed rules. Existing research systems can detect mispronunciations at the phoneme level but cannot tell a learner which Arabic letter they got wrong — so the feedback isn't usable. Bayaan fixes that with a hybrid design and reports a new metric, Feedback Grounding Rate (FGR): the share of detected errors that are mapped to a specific Arabic letter with a correction. Existing systems score FGR = 0%; Bayaan is built to score ~100%.

The key idea: split Tajweed rules into two classes and use the cheapest correct tool for each.

Class A vs Class B

ClassHow detectedRulesWhy
A — text-determinable Deterministic rule engine: compares the ASR transcript to the expected text. No ML. Idgham, Iqlab, Ikhfaa, Izhar Exact when the transcript is right; ML would only add noise.
B — acoustically-dependent Small binary classifier on the audio (frozen wav2vec2 + 2-layer head). Ghunnah, Madd (this report) Duration / nasality is only measurable from the audio signal.

The rule engine always localizes where a rule occurs (from text), so every violation — Class A or B — carries its Arabic character + position. That is what makes FGR ≈ 100%.

3. Methodology — what we did, step by step

  1. Environment. Python 3.13 venv; PyTorch 2.6 + CUDA on an RTX 3050 (4 GB) GPU.
  2. Data prep. Downloaded QDAT (obadx/qdat, MIT licence), decoded all 1,505 clips to 16 kHz mono WAV, and built a labelled table (labels.csv) with a stratified train / val / test split per rule. Label meaning: 1 = correct, 0 = incorrect.
  3. Feature caching. The wav2vec2 backbone is frozen, so we ran it once over each clip (at its true length) and cached the 1024-dim embedding. Training the small head on cached vectors then takes seconds and fits the 4 GB GPU.
  4. Training. One binary classifier per rule = frozen wav2vec2-large-xlsr-53-arabic backbone + a 2-layer head (1024 → 256 → 1). Class imbalance handled with pos_weight; early stopping on validation F1.
  5. Export. Both classifiers exported to ONNX and numerically verified against PyTorch (match to ~1e-5) at two clip lengths.
  6. Rule engine + hybrid (Class A). Implemented the Arabic phonology + Tajweed engine, deterministic Class A detection, the hybrid merge layer, and the FGR metric. 25 unit tests.
  7. IQRA-comparable scoring. Built a first-pass bridge that converts our character-level violations into the phoneme-deviation scoring used by the IQRA benchmark.
  8. Real-audio dry run. Wired a real Whisper transcript into the pipeline and ran it on real audio to validate the full chain.
  9. Safety guard. Added a transcript-reliability gate so a failed/garbage ASR output makes Class A abstain instead of producing false positives.

5.2 Feedback Grounding Rate (the novel metric)

FGR = 100% on all produced output: every flagged violation carried its Arabic character and an expected-pronunciation description. For comparison, every IQRA 2026 system scores FGR = 0% (they emit phonemes with no character mapping).

5.3 Safety guard — false positives on correct recitations

In a real-audio dry run, a weak ASR model (whisper-tiny) produced garbage transcripts, which made the rule engine wrongly flag errors. We added a reliability gate: if the transcript is too unlike the reference verse, Class A abstains. Effect on correct recitations:

Takeaway: detection quality for Class A is bounded by the ASR — and now it fails in the safe direction (silence, not false accusations).

  • QDAT is one verse. The classifier may partly key on verse-specific cues; mix in EveryAyah professional recitations (correct examples) before trusting generalization.
  • Phoneme bridge is approximate. IQRA phonemizes literally, not Tajweed-collapsed, so Tajweed-rule violations don't map 1:1 to phoneme errors. Frame Bayaan as targeting a pedagogically meaningful subset of errors with full character grounding (high FGR).
  • Madd leans to recall (R 0.96, P 0.87): it occasionally flags correct audio. For a learner app, tune the decision threshold to reduce false alarms before the user study.

7. How to reproduce

Code lives in bayaan-ml/ (sibling of the bayaan-research docs repo).

# 1. environment
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt

# 2. data: QDAT -> 16 kHz WAVs + labels.csv
python -m src.dataset --hf-id obadx/qdat

# 3. cache frozen-backbone embeddings, then train the head (per rule)
python -m src.extract_features --rule ghunnah
python -m src.train --rule ghunnah --from-features --epochs 60
python -m src.extract_features --rule madd
python -m src.train --rule madd --from-features --epochs 60

# 4. export + verify ONNX
python -m src.export_onnx --rule ghunnah --checkpoint checkpoints/ghunnah_best.pt --output models/ghunnah.onnx
python -m src.export_onnx --rule madd    --checkpoint checkpoints/madd_best.pt    --output models/madd.onnx

# 5. tests (no GPU / no download needed)
python -m pytest tests/ -q

# 6. real-audio dry run on local clips
python -m src.dryrun_local --limit 5 --asr-model openai/whisper-tiny

8. Recommended next steps

  1. Plug in a real Quran-tuned Whisper — Groq whisper-large-v3 (set GROQ_API_KEY) or a Quranic LoRA model. This is the single biggest lever for the text-based (Class A) rules. Harness already supports --asr local|groq.
  2. Augment training data with EveryAyah correct recitations to break the single-verse dependency, then re-check val F1.
  3. Threshold calibration on the validation set (esp. Madd) to reduce false positives.
  4. Phase 9 — QuranMB.v2 evaluation (locked until then): produces the IQRA-comparable F1 and the headline FGR number for the paper.
  5. Quantize ONNX (int8) if the on-device / lightweight claim is needed.
